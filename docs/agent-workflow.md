# Kasane — Developer & Agent Workflow

Практическое руководство для разработчика по совместной работе с **OpenAI Codex CLI** (основной агент разработки) и **Antigravity CLI** (`agy`, сопровождение инфраструктуры, ревью и аудит).

---

## 1. Запуск Codex в проекте

Codex CLI запускается прямо в корне репозитория:

```bash
cd ~/vibeplayer
codex
```

Для выполнения разовой команды без входа в интерактивный режим (non-interactive):
```bash
codex exec "Твой запрос"
```

## 2. Обнаружение и вызов Skills

### 2.1. Где лежат навыки
- **Проектные навыки (общие для Codex и Antigravity)**: `.agents/skills/`
  - `kasane-context` — быстрая навигация без сканирования всего репо.
  - `kasane-debug` — систематическая 8-шаговая диагностика дефектов.
  - `kasane-ui` — разработка Compose UI и визуальная верификация Previews.
  - `kasane-verify` — комплексный прогон тестов, сборок и отчёт с уровнями доказательств.
  - `impeccable` — дизайн-аудит, типографика и полировка UI.
- **Глобальные личные навыки разработчика**: `~/.agents/skills/`
  - `task-planner` — превращение короткого пожелания в строгую инженерную спецификацию.
  - `review-changes` — аудит `git diff`, чистоты кода и рисков регрессий.
- **Официальные системные Android Skills**: установлены через `android skills add`:
  - `android-cli`, `jetpack-compose-performance`, `edge-to-edge`, `testing-setup`, `android-profiler`.

### 2.2. Как агент выбирает навык
В каждом навыке в файле `SKILL.md` задан манифест с YAML frontmatter (`name` и `description`). Codex и Antigravity автоматически считывают описания и применяют подходящий навык, когда запрос соответствует его назначению.

### 2.3. Как вызвать навык вручную
Просто сошлись на имя навыка в запросе:
> «Codex, используй навык **`kasane-context`** и найди реализацию очереди воспроизведения».
> «Codex, примени протокол **`kasane-debug`** для локализации сбоя в MediaSession».

## 3. Практические примеры запросов (Cookbook)

### Пример 1: Быстрое вхождение в контекст задачи
```text
Codex, используй kasane-context. Мне нужно понять, как устроен переход между треками в Media3. Загрузи минимальный набор файлов и опиши цепочку вызовов.
```

### Пример 2: Исправление бага воспроизведения
```text
Codex, найди причину, по которой кнопка Next не переключает трек через MediaSession. Используй протокол kasane-debug: определи симптом, найди код в PlaybackManager, проверь тесты и предложи минимальный фикс без смены архитектуры.
```

### Пример 3: Изменение экрана / UI
```text
Codex, обнови карточку в TrackRow.kt по дизайн-системе Kasane. Используй навык kasane-ui: отрежь лишние отступы, примени KasaneRose для активного трека, сгенерируй Compose Preview через Android CLI и проверь полученный PNG.
```

### Пример 4: Финальная проверка перед сдачей
```text
Codex, выполни протокол kasane-verify: запусти юнит-тесты Android и Rust, проверь сборку APK и предоставь отчёт с доказательствами (что проверено, что прошло, риски).
```

### Пример 5: Планирование крупной фичи
```text
Codex, примени task-planner. Я хочу сделать офлайн-кэширование обложек в Room. Составь краткий план: критерии приёмки, затрагиваемые файлы и риски.
```

### Пример 6: Аудит перед коммитом
```text
Codex, запусти review-changes. Проверь текущий git diff, убедись, что нет отладочного кода, ненужных unwrap() и тесты покрывают изменения.
```

## 4. Разделение ролей: Codex vs Antigravity (`agy`)

| Задача | Рекомендуемый агент | Причина |
|---|---|---|
| Написание фич, компонентов, логики | **Codex CLI** | Основной coding agent проекта |
| Глубокий рефакторинг Media3 / Room / Rust | **Codex CLI** | Прямая работа с кодом приложения |
| Инспекция и обслуживание инфраструктуры | **Antigravity CLI** | Управление окружением, skills, документацией |
| Анализ Compose Previews визуально | **Codex** или **Antigravity** | Оба умеют работать со сгенерированными PNG |
| Актуализация архитектурных карт и README | **Antigravity CLI** | Быстрое ведение проектной базы знаний |

## 5. Экономия контекста и best practices

1. **Не проси агента перечитывать весь проект**: Навык `kasane-context` специально ориентирует агента на `docs/agent-map.md`, чтобы считывать только 1–2 нужных файла.
2. **Не смешивай платформы**: Если задача про Android, явно указывай платформу в запросе.
3. **Не требуй повторения архитектуры**: Контекст уже зафиксирован в `AGENTS.md` и `docs/architecture/`. Достаточно короткого технического описания задачи.
