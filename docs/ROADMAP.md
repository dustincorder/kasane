# Roadmap

Редакция 2026-11-23, заменяет план от 16.11 (доступен в git; его продуктовые цели перенесены в
`PRODUCT_SPEC.md` §3 как неподтверждённые). Этапы упорядочены по зависимостям. D1 и D2 приняты
владельцем: целевые клиенты — Android и Compose desktop на KMP; Tauri/Rust заморожен.

**Статус на 2026-11-25 (подготовка 0.2.0-alpha).** Этап 1 закрыт (миграции Room, Connect
interop, `DesktopPlayerTest` на фейковом движке). Этап 2 закрыт по существу: общая
`QueuePolicy` (включая `anchoredRadio`), порог записи истории + watch-report, единый выбор
потока остаётся частично (KI-7). Этап 3: общие данные перенесены в `:shared` (offline, lyrics,
metadata, настройки-сессия); desktop-вход через системный WebKitGTK + Secret Service —
сделано; `SessionMode`/onboarding-гейт — сделано. Connect: discovery починен (QU-бит,
реанонс), арбитр исполнителя и transfer по протоколу — сделано. Открыто: этап 4 (общий UI),
этап 5 (MPRIS, открытие файла), KI-7/остатки KI-2/CI (KI-5).

## Этап 0. Гигиена (не зависит от D1; малый риск)

1. Закоммитить или отбросить 4 изменённых файла `desktop-compose/` (KI-3) — решение владельца.
2. Включить CI на push с `scripts/verify.sh`, добавить Gradle (KI-5).
3. Удалить или пометить устаревшие документы (KI-2) — список в `CLAUDE.md`; удаление требует
   подтверждения владельца.
4. Выровнять версии (KI-6).

## Этап 1. Страховка перед переносами

Зависимости: нет. Риск: низкий. Нужен до любых изменений общих модулей.

1. Тесты миграций Room (KI-12).
2. Interop-тест Connect в стандартном прогоне (KI-11).
3. Тесты `DesktopPlayer` на фейковом движке (KI-21) — потребует вынести интерфейс из `MpvEngine`.

## Этап 2. Единая логика воспроизведения (после D1)

Зависимости: этап 1. Риск: высокий — затрагивает воспроизведение на Android; каждый шаг отдельным
изменением с неизменным поведением.

1. `StreamSelector` в `:shared`: одна цепочка выбора потока; Android-`HlsPlayerResolver` переходит на
   `IosHlsResolver`; версии клиентов YouTube — в одном месте (KI-7).
2. `RadioController` в `:shared`: извлечь из `PlaybackService` и `DesktopPlayer` (KI-8).
3. Контракт `PlayerController` + общий контрактный тест; выровнять удаление текущего трека и
   момент записи истории (KI-9, KI-10).
4. Исправить устаревшие сообщения Compose desktop (KI-19, KI-22).

## Этап 3. Общие данные и аккаунт

Зависимости: этап 1; для desktop-входа — D1(a). Риск: средний (данные пользователя).

1. `LibraryRepository` (избранное, история) в `:shared` с портом хранилища; Android остаётся на Room
   без смены схемы; desktop — атомарное хранилище вместо текущего JSON (KI-20).
2. Перенести в `:shared` без изменения поведения: `CloudLikes`, `CatalogCache`, `PlaylistPicker`,
   `HomeComposer`, `OfflinePolicy`, модель настроек (включая `autoplay`, KI-13). По результатам
   аудита Android-зависимостей у них нет, кроме `org.json` в двух файлах.
3. Desktop: `SessionStore` на Secret Service и захват входа (способ — открытый технический вопрос:
   системный WebKitGTK по образцу верификатора или импорт сессии Tauri). После этого библиотека
   аккаунта и лайки работают на общем коде.

## Этап 4. Общий UI

Зависимости: этапы 2–3. Риск: средний (внешний вид Android не должен измениться — нужны снимки).

Порядок: строка трека и меню (сейчас три реализации, общая `TrackListItem` не используется) →
страницы каталога → поиск → Home → библиотека. Навигация и Now Playing остаются платформенными.
Попутно разгрузить `KasaneApp.kt` (KI-15).

## Этап 5. Интеграция с Linux и вывод Tauri

Зависимости: D1(a), этапы 2–3. MPRIS и медиа-клавиши, открытие локального файла, дистрибутив.
Tauri и Rust удаляются только после строки-в-строку паритета по `FEATURE_MATRIX.md` и согласия
владельца.

## Этап 6. Новые функции

Только после этапов 2–3, чтобы каждая делалась один раз: локальные файлы (D4), управление
плейлистами, офлайн на desktop, остальное из `PRODUCT_SPEC.md` §3 по приоритету владельца.

## Риски

- YouTube может сломать воспроизведение в любой момент; это прерывает план и имеет приоритет.
- Переносы в `:shared` меняют рабочий Android-клиент: без этапа 1 регрессии останутся незамеченными.
- Если D1 не принято, каждая новая функция увеличивает расхождение трёх клиентов.
