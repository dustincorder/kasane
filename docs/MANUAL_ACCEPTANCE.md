# Ручная приёмка Kasane — чек-лист

Артефакты (проверены 2026-11-25):
- **Android APK**: `android/app/build/outputs/apk/release/app-release.apk` (~15,7 МБ, v2-подпись OK, `cord.kasane.music` 0.1.1-alpha)
- **Desktop**: `~/.local/opt/kasane-compose/` — установлен; запуск из меню (`.desktop` → `bin/kasane-compose-java`) или `./bin/kasane-compose-java` (Java не нужна, рантайм в комплекте). Прямой запуск ELF `bin/kasane-compose` допустим, но пишет один косметический coredump при старте (bug jpackage-лаунчера, см. KI-31).

Платформы: `[A]` Android · `[D]` Compose Desktop · `[A+D]` оба.

## Предусловия окружения [D]

- [ ] `mpv` в PATH (без него нет звука)
- [ ] `webkit2gtk-4.1`, `javascriptcoregtk-4.1`, `gtk-3` установлены — иначе гостевой фолбэк обрывается ~29 с
- [ ] Живой X11/Wayland display; без него верификатор недоступен
- [ ] Secret Service (gnome-keyring/KWallet) — без него вход не сохраняется
- [ ] Сеть для каталога и потоков

## 1. Обновление поверх существующей установки — ПЕРВЫЙ ШАГ

- [ ] `[A]` Установить APK поверх установленной версии **с данными** (история, лайки, сохранённые треки). Открыть приложение.
  **Ожидаемо:** запуск без краша; история, библиотека, офлайн-треки на месте (миграция Room v8→v9); настройки сохранены. *При потере данных — blocker, приёмку остановить.*

## 2. Первый запуск и аккаунт

- [ ] `[A+D]` Холодный старт при сохранённой сессии: показывается splash «Проверка сессии…» (не мигает онбординг), затем вход восстанавливается сам. Если до этого был выбран «Continue as a guest», гость НЕ воскрешает старую сессию.
- [ ] `[A+D]` Гостевой путь через онбординг: Home грузится, трек играет, кнопки лайк/плейлисты недоступны или скрыты.
- [ ] `[A+D]` Вход в аккаунт YouTube Music: кнопка входа показывает фазу («Preparing…» → «Checking your account…») и **не блокируется ~30 с**; после входа профиль показывает аккаунт, Liked songs грузятся, вкладки Playlists/Albums/Artists наполнены, появляется история аккаунта.
- [ ] `[A+D]` В настройках/онбординге тумблер «Work offline» действительно режет весь трафик (см. §4); после переключения Online↔Offline остальные настройки НЕ сбрасываются.
- [ ] `[D]` Перезапуск приложения → сессия сохранена (Secret Service).
- [ ] `[A+D]` Logout → данные аккаунта скрыты; повторный вход в другой аккаунт → истории не смешиваются.

## 3. Воспроизведение

- [ ] `[A+D]` Реальный трек до конца: позиция идёт, следующий трек из очереди/радио стартует сам.
- [ ] `[A+D]` Seek по треку (несколько точек): позиция прыгает на цель, звук не сбрасывается на начало.
- [ ] `[A+D]` «Start radio» на текущем треке: трек НЕ перезапускается, продолжает играть с той же позиции; подборка догружается в хвост очереди (continuation), дедуп против уже прослушанного.
- [ ] `[A]` Сворачивание приложения и блокировка экрана: звук продолжается, системный медиа-контрол (уведомление/экран блокировки/наушники) управляет воспроизведением.
- [ ] `[A+D]` Pause/resume, next/prev, repeat, shuffle — состояние кнопок совпадает с поведением.
- [ ] `[A+D]` Очередь: play next вставляет после текущего; перемещение/удаление работает; удаление текущего → играет следующий.
- [ ] `[A]` Прослушивание ≥30 с записывается в историю (и уходит в YTM-историю при входе); короткий пропуск (<30 с) НЕ записывается.

## 4. Офлайн

- [ ] `[A+D]` «Save offline» на треке → статус Downloading → Saved; трек виден в Downloads.
- [ ] `[A+D]` Включить Offline Only → выключить сеть (или режим сам режет трафик): поиск идёт по сохранённому, сохранённый трек играет **без сети**, сетевой трек даёт понятное сообщение, а не тишину.
- [ ] `[A]` Прерванная загрузка (выключить сеть посреди) → resume догружает; после 3 неудач — статус с понятной причиной и кнопка Retry.
- [ ] `[A]` Трек, который игрался только стримингом (не сохранённый) → попытка Save даёт честную ошибку, не вечный retry.

## 5. Тексты песен

- [ ] `[A+D]` Пункт «Lyrics» в меню трека открывает панель/шит для выбранного трека (не только текущего).
- [ ] `[A+D]` Трек с известным текстом: строки подсвечиваются синхронно (слово-в-слово если источник даёт word-таймкоды), тап по строке → seek, ручной выбор источника, смещение ±250 мс.
- [ ] `[A]` Lyrics доступны для сохранённого трека без сети.
- [ ] `[A+D]` Три состояния корректны: есть текст (показан), текста нет ни у одного источника (понятное «нет текста», не ошибка), источник недоступен по сети (понятная ошибка, не «нет текста»).

## 6. Connect (на двух физических устройствах)

- [ ] `[A+D]` **Двустороннее обнаружение**: телефон видит desktop И desktop видит телефон в списке устройств. Desktop должен появиться у телефона в течение ~1 мин (периодические анонсы); проверить и запуск browse ПОСЛЕ старта desktop (поздний приём).
- [ ] `[A+D]` Смена сети на desktop (Wi-Fi↔Ethernet) → анонсы перебиндятся, телефон снова видит desktop.
- [ ] `[A+D]` Сопряжение телефон↔desktop: коды совпадают, доверие сохраняется.
- [ ] `[A+D]` Удалённое состояние: с одного устройства виден трек/позиция/очередь другого; отмечено, кто исполнитель (role/activeId).
- [ ] `[A+D]` Remote pause/play/seek/gromkost' работают в обе стороны.
- [ ] `[A+D]` **Transfer playback** («Play on X»): воспроизведение продолжается на цели с той же позиции; источник встаёт на паузу — **в любой момент звук идёт только с одного устройства** (нет двойного воспроизведения).
- [ ] `[A+D]` **«Play here»**: старт воспроизведения на этом устройстве автоматически останавливает воспроизведение на другом (claim/yield).
- [ ] `[A+D]` Transfer несколько раз подряд (A→B→A); разрыв сессии посреди transfer — обе стороны остаются в согласованном состоянии.
- [ ] `[A+D]` Отключение устройства из списка → команды от него отклоняются («device is not paired»).

## 7. UX и состояния (по UX_GUIDELINES/SCREEN_SPEC)

- [ ] `[A+D]` Главные действия в 1–2 тапа: воспроизвести, в очередь, лайк, сохранить.
- [ ] `[A+D]` Пустые/загрузочные/ошибочные состояния экранов честные (Home без сети, пустая библиотека, пустая очередь) — без технических терминов (resolver, stream, error code).
- [ ] `[A]` Поворот/узкое окно; `[D]` ресайз окна и Ctrl +/−/0 — разметка не ломается.
- [ ] `[A+D]` Меню трека (долгое нажатие/ПКМ) во всех списках даёт одинаковый набор действий.

## Известные допущения (не дефекты приёмки)

- Гостевые потоки без верификации обрываются ~29 с — ограничение YouTube.
- На Desktop нет MPRIS/трея/медиа-клавиш — этап 5 roadmap.
- Переименование/удаление пользовательских плейлистов отсутствует в провайдере — gap (не реализовано, меню показывает доступные действия).
- Прямой запуск ELF `bin/kasane-compose` пишет один косметический coredump при старте (баг jpackage-лаунчера, KI-31); запуск через меню/`kasane-compose-java` — без дампов.
- Подпись APK читается из `~/.glazegram/` (KI-18) — особенность этой сборочной машины.
