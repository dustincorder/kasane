# Kasane Systematic Debugging Protocol

Систематический протокол локализации и исправления дефектов в Kasane без слепых правок и лишних переписываний архитектуры.

## 8-Шаговый протокол диагностики

1. **Получи точный симптом**:
   - Что именно не работает (например: «Next не переключает трек», «крэш при открытии пустого плейлиста», «MediaSession не обновляет метаданные»)?
   - Какая платформа затронута (Android или Linux Desktop)?

2. **Локализуй связанный код**:
   - Используй `docs/agent-map.md`, чтобы найти ответственный компонент:
     - Очередь и воспроизведение Android: `PlaybackManager.kt`, `PlaybackService.kt`.
     - InnerTube API / парсинг стримов: `MusicProvider.kt` (Android) или `crates/vibe-providers` (Linux).
     - База данных / недавние треки: `KasaneDatabase.kt` / `TrackDao` (Android) или `crates/vibe-db` (Linux).
     - Реактивное состояние UI: `KasaneApp.kt`, `MiniPlayer.kt`, `NowPlayingSheet.kt`.

3. **Собери логи и проанализируй тесты**:
   - Android: проверь существующие тесты `cd android && ./gradlew testDebugUnitTest`.
   - Linux / Rust: проверь сьют `cargo test`.
   - Изучи сообщения об ошибках или трассировки стека (stack trace).

4. **Установи воспроизводимый сценарий**:
   - Сформулируй минимальный сценарий шагов: Начальное состояние → Действие → Ожидаемый результат → Фактический результат.

5. **Сформулируй 1-2 гипотезы первопричины**:
   - Проверь типичные зоны риска:
     - *Media3*: не вызван ли `player.prepare()`? Заполнен ли `MediaItem` корректным `MediaMetadata`? Есть ли гонка в корутинах при обновлении `StateFlow`?
     - *InnerTube*: валиден ли формат URL потока? Не истёк ли токен или не заблокирован ли запрос? (Не меняй версию клиента наугад!).
     - *Room / SQLite*: правильный ли поток диспатчера (`Dispatchers.IO`), нет ли блокировок главного потока UI?
     - *Compose*: не теряется ли состояние при рекомпозиции (отсутствие `remember`, неверные ключи в `key(...)` или `LazyColumn`)?

6. **Проверь первопричину доказательно**:
   - Убедись в гипотезе с помощью точечного лога, проверки кода или целевого unit-теста.

7. **Внеси минимальное изолированное исправление**:
   - Не переписывай соседние модули.
   - Соблюдай правила: никаких `unwrap()` в Rust, сохранять чистую обработку исключений в Kotlin.

8. **Проверь отсутствие регрессий**:
   - Запусти юнит-тесты (`./gradlew testDebugUnitTest` или `cargo test`).
   - Запусти `kasane-verify` для финальной проверки сборки и тестов.
